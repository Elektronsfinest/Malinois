# Plan: Case Management (Spec 003)

## Backend changes

- **Files affected (`apps/api/`):**
  - `models.py` — Add `Case` model (`__tablename__ = "cases"`) with `id`, `case_number` (`String(100)`, nullable, unique, indexed), `title` (`String(255)`, not null, indexed), `client_name` (`String(255)`, not null, indexed), `assigned_to` (`Integer`, FK `users.id` named `fk_cases_assigned_to_users`, not null, indexed), `deadline` (`Date`, nullable, indexed), `date_filed` (`Date`, nullable), `status` (`String(20)`, not null, `server_default="open"`), `archived` (`Boolean`, not null, `server_default=false()`, indexed), `version` (`Integer`, not null, `server_default="1"`), `extra_fields` (`JSON`, nullable), `created_at` (`DateTime(timezone=True)`), `updated_at` (`DateTime(timezone=True)`), plus `assignee` relationship to `User`.
  - `alembic/versions/<rev>_add_cases_table.py` — Autogenerated migration creating `cases` table + indices + named FK (`SQLite` + `PostgreSQL` compatible using `sa.JSON()`, `sa.false()`, `server_default="1"`).
  - `schemas.py` — Add `CaseStatus = Literal["open", "closed"]`, `AssignableUserResponse` (`id`, `email`, `role`, `is_active`), `CaseResponse` (includes `assigned_to_email`, `assigned_to_is_active`, `extra_fields`), `CaseListResponse` (`items`, `total`, `page`, `page_size`), `CaseCreateRequest`, and `CaseUpdateRequest` (requires `version: int`, optional `title`, `client_name`, `status`, `case_number`, `assigned_to`, `deadline`, `date_filed`, `extra_fields`, `reason`).
  - `services/audit.py` — Add `log_case_changes(case_id, actor_id, changes, reason)` hook (redacting sensitive keys like `pesel` from logs; to be backed by `case_edit_log` in Spec 009).
  - `services/cases.py` *(new)* — Unified case service layer enforcing:
    - Role visibility scope (`user`: own; `supervisor`: own + direct subordinates; `admin`: all).
    - `list_cases(db, actor, page, page_size)` — excludes archived by default, sorts by `deadline ASC NULLS LAST, id ASC`, returns `(items, total)`.
    - `get_case_in_scope(db, actor, case_id)` — returns `404 Not Found` if non-existent or out of scope (anti-enumeration).
    - `list_assignable_users(db, actor)` — `supervisor`: self + direct subordinates (including inactive); `admin`: all users (including inactive); `user`: `403`.
    - `create_case(db, actor, payload)` — `user` → `403`; `supervisor` → `403` on non-null dates or out-of-team `assigned_to`; `admin` → full creation; `assigned_to` may be active or inactive (`400` if user doesn't exist); duplicate `case_number` → `400`.
    - `update_case(db, actor, case_id, payload)` — `404` if out of scope; `400` if `archived == True`; `409 Conflict` with `{ detail, current }` if `version` mismatch; `403` if non-admin modifies `deadline`, `date_filed`, `case_number`, or `assigned_to`; `400` if admin actually changes `deadline`/`date_filed` without non-empty `reason` (≤500 chars); atomic `version + 1` and `log_case_changes`.
  - `services/users.py` — Wire `get_blocking_case_ids(db, user_id)` to query active (`archived == False`) cases assigned to `user_id`, and atomically reassign them (incrementing `version`) when `reassign_cases_to` is provided during user deactivation.
  - `routers/cases.py` *(new)* — Thin route handlers:
    - `GET /api/cases`
    - `POST /api/cases`
    - `GET /api/cases/{case_id}`
    - `PATCH /api/cases/{case_id}`
    - `GET /api/users/assignable`
  - `main.py` — Include `cases_router`.
  - `seed.py` — Add 4 idempotent Polish ZUS sample cases (overdue, due within 7 days, safe future, null deadline) assigned across `trainee@example.com` and `sup@example.com`.
- **New dependencies:** None.
- **Migration needed:** Yes — creates `cases` table.

- **Files affected (`apps/web/src/`):**
  - `api/cases.ts` *(new)* — Typed API client (`CaseItem`, `CaseListResponse`, `AssignableUser`, `CaseCreatePayload`, `CaseUpdatePayload`, `CaseConflictError`, `fetchCases`, `createCase`, `updateCase`, `fetchAssignableUsers`).
  - `utils/dates.ts` *(new)* — `Europe/Warsaw` "today" helper, Polish `DD.MM.YYYY` formatter, and urgency classifier (`overdue` | `due_soon` | `safe` | `none`) using configurable threshold (default `7` days).
  - `components/AppNav.tsx` *(new)* — Shared glassmorphic top navigation bar (`Dashboard` `/`, `Sprawy` `/cases`, `Panel administratora` `/admin` for admin only, role badge, logout button).
  - `components/CasesPage.tsx` *(new)* — `/cases` main table with urgency badges, `"Zakończono"` toggle (sends `version`), inactive assignee indicator, disabled/placeholder `"Import / Edytor pliku"` button, `"Nowa sprawa"` modal (inactive users labeled `(nieaktywny)`, date inputs hidden for `supervisor`, past-deadline warning for `admin`), inline **Edytor wstępny** panel (admin-only date fields + mandatory `"Powód zmiany daty"`, `extra_fields` display/edit), and accessible `409 Conflict` modal (`role="alertdialog"`, *"Twoja wersja"* vs *"Zapisana wersja"*, *"Nadpisz"* / *"Odrzuć moje zmiany"*).
  - `components/DashboardPage.tsx` & `components/AdminPlaceholderPage.tsx` — Integrate `AppNav` so navigation between `/`, `/cases`, and `/admin` is seamless.
  - `router.tsx` — Add `/cases` route guarded by authentication.
  - `App.css` — Add styles for top nav, case table, urgency badges (`#ef4444`, `#f59e0b`, `#22c55e`, neutral), inline editor drawer/panel, modals, and past-deadline warning banner.
- **New dependencies:** None.

## Test plan

- **New pytest tests (`apps/api/tests/test_cases.py`):**
  - Role visibility matrix (`user` sees own only; `supervisor` sees own + direct subordinates; `admin` sees all; out-of-scope `GET`/`PATCH` returns `404`).
  - `GET /api/cases` pagination `{ items, total, page, page_size }`, excludes archived, sorts `deadline ASC NULLS LAST`, includes `assigned_to_email` & `assigned_to_is_active`.
  - `GET /api/users/assignable` role scoping (`user` → `403`, `supervisor` → self + subordinates including inactive, `admin` → all including inactive).
  - `POST /api/cases`: `user` → `403`; `supervisor` with null dates → `201`, with non-null date → `403`, out-of-team assignee → `403`; `admin` with past/future dates & duplicate `case_number` → `400`; assigning to an **inactive** user → `201` with `assigned_to_is_active=False`.
  - `PATCH /api/cases/:id`:
    - `user`/`supervisor` edit `title`/`client_name`/`status`/`extra_fields` → `200`, `version` incremented.
    - Non-admin editing `deadline`/`date_filed`/`case_number`/`assigned_to` → `403`.
    - Admin editing `deadline`/`date_filed` without `reason` → `400`; with `reason` → `200`; unchanged date without `reason` → `200`.
    - Archived case → `400`.
    - Stale `version` → `409 Conflict` with latest `current` case object.
  - User deactivation integration: deactivating a user with active cases without `reassign_cases_to` → `409` with `blocking_case_ids`; with `reassign_cases_to` → `200` and cases reassigned with incremented `version`.
- **New Vitest tests (`apps/web/src/CasesPage.test.tsx`):**
  - Renders `/cases` table with Polish `DD.MM.YYYY` dates and urgency badges (`Zaległa`, `Wkrótce`, `W terminie`, `Brak terminu`).
  - `user` does not see `"Nowa sprawa"` button or admin date inputs; `supervisor` sees `"Nowa sprawa"` with inactive user marked `(nieaktywny)` and without date inputs; `admin` sees date inputs + past-deadline warning + mandatory `"Powód zmiany daty"`.
  - `"Zakończono"` toggle sends `PATCH` with `version` and `status: "closed"`.
  - `409 Conflict` opens accessible `alertdialog` showing *"Twoja wersja"* vs *"Zapisana wersja"* and supports both *"Nadpisz"* and *"Odrzuć moje zmiany"*.

## Risks / Notes

- **PII Protection (`Pesel`):** `extra_fields` may store `Pesel` from ZUS Excel imports. `services/audit.py` explicitly redacts any key matching `pesel` (case-insensitive) from log output.
- **Urgency threshold:** Uses default `7` days until Spec 012 adds `/api/admin/settings` (`notification_threshold_days`).
- **Notes & Edit History panels:** Spec 009 (`case_edit_log`) and Spec 010 (`case_notes`) will plug directly into the inline **Edytor wstępny** panel created here.
