# Plan: Role-Based Access Control (Spec 002)

## Backend changes

- **Files affected (`apps/api/`):**
  - `models.py` — Add `role: Mapped[str]` (`String(20)`, `server_default="user"`, `nullable=False`), `supervisor_id: Mapped[int | None]` (`Integer`, `ForeignKey("users.id")`, `index=True`, `nullable=True`), and `must_change_password: Mapped[bool]` (`Boolean`, `server_default=false()`, `nullable=False`) to `User`.
  - `alembic/versions/<rev>_add_user_roles_and_supervisor.py` — Autogenerated batch migration (`render_as_batch=True`) adding the three columns, index, and self-referential FK on `users`.
  - `security.py` — Pin `bcrypt.gensalt(rounds=12)`; add `validate_jwt_secret()` (rejects dev default when `ENV=production`); add `validate_password_policy(password: str)` (min 12 chars, max 72 UTF-8 bytes, ≥1 upper, ≥1 lower, ≥1 digit, ≥1 non-alphanumeric non-whitespace special char).
  - `main.py` — Call `validate_jwt_secret()` in `lifespan` startup and include `admin_users_router`.
  - `schemas.py` — Add `UserRole = Literal["admin", "supervisor", "user"]`; extend `UserResponse` with `role`, `supervisor_id`, `must_change_password`; add `AdminUserCreateRequest`, `AdminUserUpdateRequest`, and `DeactivationConflictResponse`.
  - `routers/auth.py` — Split auth dependency into:
    - `get_authenticated_user`: validates Bearer JWT (`sub`-only) and `user.is_active` (used by `GET /api/me` and future `PATCH /api/me/password`).
    - `get_current_user`: depends on `get_authenticated_user`, raises `403` with `{"code": "password_change_required", "detail": "Musisz zmienić hasło przed kontynuowaniem."}` when `must_change_password` is `True`.
    - `require_role(*roles: UserRole)`: reusable FastAPI dependency factory returning `403 Forbidden` for unauthorized roles.
  - `services/audit.py` *(new)* — Thin `log_admin_action(actor_id, action, target_user_id, details)` helper using Python's `logging` module (to be backed by `admin_audit_log` in Spec 009).
  - `services/users.py` *(new)* — Business logic for listing users with filters (`role`, `supervisor_id`, `is_active`), creating users (validating email uniqueness, password policy, `supervisor_id` rules, setting `must_change_password=True`), and updating/deactivating users atomically (self-lockout & last-admin guard, auto-clear `supervisor_id` on promotion to `supervisor`/`admin`, preserve subordinates on `supervisor` ↔ `admin`, `409 Conflict` with `blocking_subordinate_ids` / `blocking_case_ids` hook when demoting to `user` or deactivating with active subordinates/cases).
  - `routers/admin_users.py` *(new)* — Thin route handlers for `GET /api/admin/users`, `POST /api/admin/users`, `PATCH /api/admin/users/:id`, all guarded by `Depends(require_role("admin"))`.
  - `seed.py` — Keep `trainee@example.com` / `Secret123!` (`role="user"`, `must_change_password=False`) for backward compatibility with existing tests; add idempotent dev seeds: `admin@example.com` (`AdminPass123!`), `supervisor@example.com` (`SuperPass123!`), and `user@example.com` (`UserPass1234!`, `supervisor_id=supervisor.id`).
- **New dependencies:** None.
- **Migration needed:** Yes — adds `role`, `supervisor_id`, and `must_change_password` columns to `users` table (SQLite + PostgreSQL compatible via `render_as_batch=True`).

## Test plan

- **New pytest tests (`apps/api/tests/`):**
  - `test_security.py` — `validate_password_policy` (too short, >72 UTF-8 bytes, missing upper/lower/digit/special, whitespace-only special, valid 12+ char password), `bcrypt` cost factor ≥12, `validate_jwt_secret` rejecting dev default when `ENV=production`.
  - `test_rbac.py` —
    - `GET /api/me` and `POST /api/login` return `role`, `supervisor_id`, `must_change_password`.
    - `must_change_password=True` allows `GET /api/me` (`200`) but blocks protected routes with `403` + `code: "password_change_required"`.
    - `require_role` role matrix (`admin`, `supervisor`, `user`, unauthenticated) on `GET/POST /api/admin/users` and `PATCH /api/admin/users/:id`.
    - `GET /api/admin/users` returns active + inactive users and supports `?role=`, `?supervisor_id=`, `?is_active=`.
    - `POST /api/admin/users`: valid creation (`201`, `must_change_password=True`), duplicate email (`400`), weak password (`400`), invalid/inactive/non-supervisor-or-admin `supervisor_id` (`400`), `supervisor`/`admin` with non-null `supervisor_id` (`400`).
    - `PATCH /api/admin/users/:id`:
      - Admin self-deactivation / self-demotion → `400`.
      - Last active admin deactivation / demotion → `400`.
      - `user` → `supervisor`/`admin` auto-clears `supervisor_id = None`.
      - `supervisor` ↔ `admin` preserves direct subordinates.
      - `supervisor`/`admin` → `user` with subordinates without `reassign_subordinates_to` → `409` with `blocking_subordinate_ids`; with valid target → `200` and subordinates reassigned atomically.
      - Deactivating `supervisor`/`admin` with subordinates without `reassign_subordinates_to` → `409`; with valid target → `200` and deactivated + reassigned atomically.
      - Deactivating user with `reassign_cases_to` pointing to inactive/missing user → `400`.
      - Self-supervision (`supervisor_id == id`) → `400`.
      - Deactivated user's existing JWT immediately returns `401`.
  - `test_database.py` — Update user model column assertions to include `role`, `supervisor_id`, `must_change_password`.
- **New Vitest tests (`apps/web/src/`):**
  - Update `App.test.tsx` mock `User` objects to include `role`, `supervisor_id`, `must_change_password`.
  - Add RBAC UI tests:
    - `admin` user sees `"Administrator"` role badge and `"Panel administratora"` link and can navigate to `/admin`.
    - `user` and `supervisor` roles see their respective Polish role badges, do NOT see the `/admin` link, and navigating directly to `/admin` redirects to `/`.
- **E2E coverage:** Existing Playwright login/dashboard flow continues passing against `trainee@example.com`; no new E2E spec required until Spec 003/012 UIs land.

## Risks / Notes

- **Spec 003 (`cases` table) not yet implemented:** `get_blocking_case_ids(db, user_id)` in `services/users.py` will return `[]` until Spec 003 wires up the `cases` query. `reassign_cases_to` is still validated if provided.
- **Spec 008 (`PATCH /api/me/password`) not yet implemented:** Newly created users via `POST /api/admin/users` have `must_change_password=True` and will be blocked by `get_current_user` (while still able to call `GET /api/me`) until Spec 008 adds `PATCH /api/me/password`. Dev seed users have `must_change_password=False` so local development is unblocked.
- **Spec 009 (`admin_audit_log`) not yet implemented:** `services/audit.py` logs structured entries to Python's logger now and will be swapped to DB persistence in Spec 009.
- **Case visibility (`GET /api/cases`, `PATCH /api/cases/:id`):** Those endpoints belong to Spec 003, which builds directly on `get_current_user` and `require_role` delivered here.
